# レビューの記録

作りながらサブエージェントに3回、批判的なレビューをさせました。指摘ごとに、採用したか、採用しなかった場合はその理由を残します。

## 1回目：設計（データモデルと画面構成）

### 採用した指摘
| 指摘 | 対応 |
|---|---|
| localStorage の容量（約5MB）を数万件で超える | 通常は localStorage に保存し、容量不足になったら自動で IndexedDB に切り替える（3万件・約9MBで確認） |
| 読み込みに失敗したデータを空データで上書きしてしまう | 読み込みに失敗したら保存を止め、「書き出す／復元／退避して新しく始める」を選ぶ画面を出す |
| マイグレーション前のデータが失われる | 移行前の元データを `kakeibo.data.pre-v<番号>` に退避する。自分より新しい schemaVersion のデータには書き込まない |
| JSON バックアップにレシート画像が入らない | 画像を Base64 で含めるか選べるようにした |
| CSV で情報が落ちる・再読み込みで重複する | ID 列・振替先・お店・タグの列を持たせ、同じ ID は上書きにした |
| 繰り越しをあとから ON にすると過去までさかのぼって変わる | ON にした月（`carryoverSince`）から計算する。超過分（マイナス）は繰り越さないと画面に明記 |
| 1日あたりの額が曖昧 | 予定の明細と、まだ登録されていない今月の固定費を差し引き、切り捨てで計算 |
| 将来予測で分割払いを二重に数える | 「ふだんの支出」の平均から定期・分割を除き、データが7日未満なら平均を使わない |
| 引き落とし口座の残高が足りるか知りたい | クレカ予測に、支払日時点の引き落とし口座の残高見込みと「残高不足」警告を追加 |
| 支払日の土日 | 翌月曜にずらす（祝日は対象外。後述） |
| 口座・カテゴリ削除時の参照切れ | 明細があるものは削除できず「非表示」に。削除時はテンプレート・定期・目標・カードの引き落とし口座の参照も外す |
| iOS などでデータが消される | `navigator.storage.persist()` を自動でリクエストし、設定にもボタンを置く。30日バックアップしていなければホームで促す |
| file:// と GitHub Pages でデータが別になる | README に明記 |
| リマインダーはアプリを閉じていると鳴らない | 開いている間だけ通知し、時刻を過ぎていれば次に開いたときにバナーで知らせると画面と README に明記 |
| パスコードが4桁だと総当たりで破られる | ソルト付きで2000回繰り返しハッシュし、5回失敗したら待ち時間を入れる。「簡易ロック」と強く明記 |
| 毎回全件を集計すると遅い | 月ごとの集計と残高をキャッシュ（変更時に作り直す）。明細は150件ずつ表示、検索は入力から200ms待って実行 |
| 入力のたびにページを移るのは面倒 | 入力はシート（モーダル）にし、数字キーボード、今日／昨日、前回の口座・カテゴリの記憶、「保存して続ける」を付けた |
| テンプレートの置き場所 | 入力シートの上部と、ホームのワンタップボタンに置いた |
| 予算・口座がスマホで見つけにくい | ホームのカードから直接たどれるようにした |
| 店名ランキングがメモの表記ゆれで割れる | 「お店・相手」欄を追加し、入力候補を出す。全角・半角と空白をそろえて集計 |
| カード引き落としの記録方法がわかりにくい | クレカ予測の行に「引き落としを記録」ボタンを置いた（振替として記録） |
| グラフのダークモード対応・読み上げ | 色を CSS 変数にし、グラフごとに「数値で見る」の表を付けた |
| 連続日数に自動登録を数えない | 手で記録した日だけを数える |

### 採用しなかった指摘
| 指摘 | 理由 |
|---|---|
| 本体は最初から IndexedDB に置くべき | 要件が「localStorage（足りなければ IndexedDB）」なので、自動切り替えにした |
| Undo は全体のコピーではなく逆操作で持つべき | 逆操作は操作の種類ごとに実装が必要でバグの元になる。コピーの合計サイズに上限（約40MB）を設け、3万件でも問題ないことを確認した |
| 返金（refund）型を追加 | 型を増やすと集計がすべて複雑になる。カードの返金は同じカードへの「収入」で記録すると、請求額から差し引かれるようにした |
| 確定した請求を statement として保存 | 締め日を変えると過去の予測が変わる点は、予測という機能の性質上許容した |
| レシート1枚を複数カテゴリに分ける | 要件外。必要なら明細を複製して金額を分けられる |
| 振替の手数料欄 | 手数料は別に支出として記録すればよい |
| 分割払いの手数料欄 | 手数料込みの総額を入れれば同じ結果になる |
| 祝日表を持つ | 毎年の更新が必要になる。土日のみ対応し、画面に「祝日は考慮していない」と明記 |
| 支払い方法と口座を統合 | 要件で両方が求められている。口座を選ぶと支払い方法が自動で入るようにして手間を減らした |
| 仮想スクロール | 150件ずつ「さらに表示」で十分速い（3万件でも明細画面の表示が約0.1秒） |
